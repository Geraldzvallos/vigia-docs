    Catálogo de endpoints de la API¶

    Generado automáticamente desde app/main.py y app/api/. La especificación interactiva (OpenAPI) está en /docs del despliegue.

    111 endpoints.

    Administración y Telemetría¶

    Método Ruta Función Descripción
    GET /api/admin/usage get_usage_dashboard Retorna el dashboard analítico de utilización de Vigía. Valida que el rango de consulta no sea posterior ni exceda los 180 días. Solo accesible para el rol ADMIN global.

    Auditoría¶

    Método Ruta Función Descripción
    GET /api/audit list_audit_logs Consulta paginada con filtros de la bitácora de auditoría. ADMIN ve todo el sistema. OWNER ve únicamente eventos de proyectos donde es OWNER. Demás roles reciben 403 Forbidden.

    Autenticación¶

    Método Ruta Función Descripción
    POST /api/auth/forgot-password forgot_password_endpoint Solicitud de restablecimiento de contraseña. Respuesta idéntica y genérica para no revelar si el correo existe o no en la plataforma.
    POST /api/auth/resend-code resend_code_endpoint Reenvía un nuevo código de 6 dígitos si el usuario existe y está pendiente de verificación. Respuesta genérica que no revela la existencia ni el estado de la cuenta.
    POST /api/auth/reset-password reset_password_endpoint Restablece la contraseña de un usuario mediante el código de 6 dígitos. Al completarse: - Incrementa token_version (cierra todas las sesiones previas). - Marca el código como usado. - Marca el correo como verificado.
    POST /api/auth/verify-email verify_email_endpoint Verifica el correo electrónico de un usuario mediante un código de 6 dígitos. Al verificar exitosamente, marca la cuenta como verificada, inicia sesión y crea la cookie de sesión.
    POST /api/login login Autenticación contra la tabla de usuarios con mitigación de enumeración y rate limiting. Genera un token firmado JWT con user_id, role, token_version y expiración.
    POST /api/logout logout Cierra la sesión y revoca la sesión actual en user_sessions incrementando token_version.
    POST /api/register register_user Registro público de nuevos usuarios (Fase A). Crea el usuario con rol USER, genera su proyecto personal donde es OWNER, asigna 2 casos de prueba de ejemplo aprobados, una suite de ejemplo y opcionalmente un perfil Oracle Demo si está configurado en el servidor.

    Autenticación Google¶

    Método Ruta Función Descripción
    GET /api/auth/google/callback google_callback Procesa el callback de Google tras el consentimiento del usuario. Valida state y nonce, verifica el ID Token, autentica o registra al usuario y emite la sesión JWT correspondiente.
    GET /api/auth/google/login google_login Inicia el flujo de autenticación OpenID Connect con Google. Genera state y nonce criptográficos, los almacena en una cookie firmada y redirige a la pantalla de consentimiento de Google.

    POST /api/repositories/ create_repository
    DELETE /api/repositories/{repository_id} delete_repository
    GET /api/repositories/{repository_id} get_repository

    Casos de Prueba¶

    Método Ruta Función Descripción
    GET /api/test-cases/ read_test_cases Obtiene la lista de casos de prueba guardados con paginación y filtro de proyecto. Si se especifica un proyecto al que no se tiene acceso, responde 404 (aislamiento). Soporta validación de caché ETag y respuesta 304 Not Modified.
    POST /api/test-cases/ create_test_case Crea un nuevo caso de prueba asignado a un proyecto. Si el rol del usuario en el proyecto es DEV, el caso queda automáticamente en estado PROPUESTO.
    DELETE /api/test-cases/{test_case_id} delete_test_case Elimina un caso de prueba de la base de datos. Exclusivo para QA, OWNER y ADMIN.
    GET /api/test-cases/{test_case_id} read_test_case Obtiene un caso de prueba específico por su ID. Si el usuario no es miembro del proyecto del caso, responde 404.
    PUT /api/test-cases/{test_case_id} update_test_case Actualiza la información de un caso de prueba. Si es editado por DEV, el estado vuelve/queda en PROPUESTO para revisión QA.
    PATCH /api/test-cases/{test_case_id}/status update_test_case_status Aprueba o rechaza un caso de prueba (PROPUESTO -> APROBADO / RECHAZADO). Exclusivo para roles QA, OWNER y ADMIN global.

    Método Ruta Función Descripción

    Corridas de prueba¶

    Método Ruta Función Descripción
    GET /api/projects/{project_id}/runs list_runs
    GET /api/runs/{run_id} get_run
    POST /api/runs/{run_id}/execute execute_pending Ejecuta los casos automáticos que quedaron pendientes (por ejemplo, SQL sin conexión al iniciar).
    POST /api/runs/{run_id}/finish finish_run Cierra la corrida, recalcula los totales, crea los tickets de los manuales fallidos y avisa por webhook.
    PUT /api/runs/{run_id}/results/{result_id} record_manual_result
    POST /api/suites/{suite_id}/runs start_run Crea la corrida con un resultado por caso y ejecuta los casos API (y SQL si llegan credenciales).

    Historial de Ejecuciones¶

    Método Ruta Función Descripción

    GET /api/history/{history_id} get_history_detail Obtiene los detalles de un registro de historial específico. Si el usuario no es miembro del proyecto de la ejecución, responde 404.

    Integración CI/CD¶

    Método Ruta Función Descripción
    GET /api/ci/runs list_ci_runs Lista las ejecuciones de pipelines (CiRun) paginadas y filtrables. Accesible para miembros con sesión del proyecto y para tokens de CI del proyecto.
    GET /api/ci/runs/{run_id} get_ci_run_detail Obtiene el detalle de un CiRun junto a sus ejecuciones históricas asociadas. Accesible para miembros del proyecto o para el token de CI del proyecto.
    POST /api/ci/trigger trigger_ci_run Dispara la ejecución automatizada de una Suite mediante Token de CI por proyecto. Solo accesible mediante autenticación de token de proyecto (vgi_...). Verifica que la suite y el perfil pertenezcan estrictamente al proyecto del token.

    Invitaciones¶

    Método Ruta Función Descripción
    GET /api/invitations get_my_pending_invitations Retorna la lista de invitaciones pendientes para el usuario en sesión. Incluye nombre del proyecto, rol y quién invitó.
    POST /api/invitations/{invitation_id}/accept accept_invitation Acepta una invitación pendiente y crea la membresía correspondiente. Solo el invitado puede aceptar (cualquier otro recibe 404). Si ya no está pendiente, responde 409.
    POST /api/invitations/{invitation_id}/decline decline_invitation Rechaza una invitación pendiente. Solo el invitado puede rechazar (cualquier otro recibe 404). Si ya no está pendiente, responde 409.

    Motor de Ejecución¶

    Método Ruta Función Descripción
    POST /api/execute/raw execute_target_sql Ejecuta una sentencia SQL aislada aplicando las políticas de seguridad del ambiente.
    POST /api/execute/suite/{suite_id} run_test_suite Ejecuta en ráfaga todos los casos de prueba de una Suite utilizando una conexión única. Regla: Solo los casos APROBADO se ejecutan en suites y en CI; los demás se reportan como omitidos en el resumen. Permitido a QA, OWNER en el proyecto, ADMIN global o CI API Key.
    POST /api/execute/test-case/{test_case_id} run_test_case Orquestador Principal: Recupera un caso de prueba guardado y lo ejecuta utilizando el servicio centralizado de ejecución. Regla: Solo se ejecutan casos en estado 'APROBADO'. Permitido a QA, OWNER en el proyecto, ADMIN global o CI API Key.

    Notificaciones¶

    Método Ruta Función Descripción
    GET /api/notifications get_my_notifications Lista las notificaciones del usuario en sesión. Incluye el total y el conteo de no leídas (unread_count).
    POST /api/notifications/read-all mark_all_notifications_read Marca todas las notificaciones pendientes del usuario como leídas.
    GET /api/notifications/unread-count get_my_unread_count Retorna respuesta mínima con la cantidad de notificaciones no leídas. Utilizado para el sondeo periódico del frontend.
    POST /api/notifications/{notification_id}/read mark_notification_read Marca una notificación propia como leída. Si la notificación no pertenece al usuario -> 404.

    Perfiles de Conexión¶

    Método Ruta Función Descripción
    GET /api/connections/ get_connection_profiles Obtiene la lista de perfiles de conexión filtrados opcionalmente por proyecto. Si el usuario no es miembro del proyecto especificado, responde 404 (aislamiento).
    POST /api/connections/ create_connection_profile Crea un nuevo perfil de conexión Oracle para un proyecto. Permitido únicamente a DBA u OWNER del proyecto, o ADMIN global. Valida contra destinos de red privada o restringidos (SSRF).
    DELETE /api/connections/{connection_id} delete_connection_profile Elimina un perfil de conexión. Permitido a DBA u OWNER del proyecto, o ADMIN global.
    GET /api/connections/{connection_id} get_connection_profile Obtiene un perfil de conexión por su ID. Si el usuario no es miembro del proyecto al que pertenece la conexión, responde 404.
    PUT /api/connections/{connection_id} update_connection_profile Actualiza la información de un perfil de conexión. Permitido a DBA u OWNER del proyecto, o ADMIN global. Los perfiles is_demo no pueden modificarse.
    POST /api/connections/{connection_id}/test test_connection_profile Prueba la conectividad de un perfil Oracle. Permitido a DBA u OWNER del proyecto, o ADMIN global. Si el perfil es de demostración (is_demo=True), inyecta automáticamente DEMO_ORACLE_PASSWORD.

    Proyectos¶

    Método Ruta Función Descripción
    GET /api/projects/ get_projects Obtiene la lista de proyectos con paginación estricta. Filtra únicamente los proyectos donde el usuario es miembro activo (ADMIN ve todo; CI ve todo). Soporta validación de caché ETag y respuesta 304 Not Modified.
    POST /api/projects/ create_project Crea un nuevo proyecto en el espacio de trabajo. Cualquier usuario autenticado puede crear proyectos y queda asignado como OWNER. Límite configurable por MAX_PROJECTS_PER_USER (por defecto 5; ADMIN sin límite).
    DELETE /api/projects/{project_id} delete_project Elimina un proyecto si el usuario es OWNER o ADMIN y no tiene dependencias activas.
    GET /api/projects/{project_id} get_project Obtiene los detalles de un proyecto por su ID. Si el usuario no es miembro, responde 404 para aislar la existencia del recurso.
    PUT /api/projects/{project_id} update_project Actualiza la información de un proyecto existente. Permitido únicamente a usuarios con rol OWNER en el proyecto o ADMIN global.
    GET /api/projects/{project_id}/ci-tokens get_project_ci_tokens Lista todos los tokens de CI del proyecto (sin exponer el secreto en claro). Solo permitido para el OWNER del proyecto o ADMIN global.
    POST /api/projects/{project_id}/ci-tokens create_project_ci_token Crea un nuevo token de CI para el proyecto. Solo permitido para el OWNER del proyecto o ADMIN global. Devuelve el token en texto plano UNA ÚNICA VEZ.
    DELETE /api/projects/{project_id}/ci-tokens/{token_id} revoke_ci_token Revoca un token de CI del proyecto. Solo permitido para el OWNER del proyecto o ADMIN global.
    GET /api/projects/{project_id}/invitations get_project_invitations Lista las invitaciones pendientes del proyecto. Solo permitido para el OWNER del proyecto o ADMIN global.
    DELETE /api/projects/{project_id}/invitations/{invitation_id} cancel_project_invitation Cancela una invitación pendiente del proyecto. Solo permitido para el OWNER del proyecto o ADMIN global.
    GET /api/projects/{project_id}/members get_project_members Lista todos los miembros del proyecto. Requiere ser miembro del proyecto o ADMIN global. Privacidad: el correo de los miembros solo debe verlo el OWNER del proyecto o un ADMIN; para el resto, la API debe devolver email = null.
    POST /api/projects/{project_id}/members add_project_member Invita a un usuario al proyecto por username o email. En Fase C, crea una invitación pendiente en vez de la membresía directa. Solo permitido a usuarios con rol OWNER en el proyecto o ADMIN global.
    DELETE /api/projects/{project_id}/members/{user_id} remove_project_member Quita un miembro del proyecto. Permitido a OWNER o ADMIN global, o al propio usuario si desea abandonar el proyecto. Protección: No se puede quitar ni salir siendo el último OWNER.
    PATCH /api/projects/{project_id}/members/{user_id} update_project_member Cambia el rol de un miembro del proyecto. Solo permitido a usuarios con rol OWNER en el proyecto o ADMIN global. Protección: No se puede degradar al último OWNER.

    Suites de Pruebas¶

    Método Ruta Función Descripción
    GET /api/suites/ get_all_suites Obtiene todas las suites registradas con paginación y filtro de proyecto accesible.
    POST /api/suites/ create_suite Crea una nueva Suite de Pruebas. Permitido para OWNER, QA y DEV del proyecto, o ADMIN.
    DELETE /api/suites/{suite_id} delete_suite Elimina una suite de prueba. Exclusivo para QA, OWNER y ADMIN.
    GET /api/suites/{suite_id} get_suite_detail Obtiene el detalle de una suite por su ID (aislado por proyecto: 404).
    PUT /api/suites/{suite_id} update_suite Actualiza nombre y descripción de una suite. Permitido para OWNER, QA y DEV.
    DELETE /api/suites/{suite_id}/test-cases/{test_case_id} remove_test_case_from_suite Retira un caso de una suite de forma controlada.
    POST /api/suites/{suite_id}/test-cases/{test_case_id} add_test_case_to_suite Vincula un Caso de Prueba a una Suite de Pruebas. Validaciones estrictas: - 404 si la suite o el caso no existen o el usuario no es miembro del proyecto. - 409 si el caso ya pertenece a la suite. - 409 si el caso y la suite pertenecen a proyectos distintos.

    Usuarios¶

    Método Ruta Función Descripción
    DELETE /api/me delete_my_account Elimina la cuenta del usuario autenticado tras confirmar su nombre de usuario. Anonimiza la evidencia histórica y limpia proyectos personales.
    GET /api/me get_me Obtiene los datos del usuario autenticado actual y sus proyectos con roles.
    PATCH /api/me update_my_profile Actualiza el nombre completo del usuario autenticado actual.
    POST /api/me/password change_my_password Cambia la contraseña del usuario autenticado. Exige la contraseña actual (salvo que sea un usuario registrado con Google sin contraseña local), valida la nueva según la política y revoca sesiones previas (incrementa token_version).
    GET /api/users/ list_users Lista todos los usuarios del sistema. Exclusivo para administradores.
    POST /api/users/ create_user Crea un nuevo usuario en la plataforma. Exclusivo para administradores.
    DELETE /api/users/{user_id} delete_user Elimina un usuario con protecciones contra autoeliminación y último administrador.
    GET /api/users/{user_id} get_user_detail Obtiene los detalles de un usuario específico por su ID.
    PATCH /api/users/{user_id} update_user Actualiza datos, rol o estado de un usuario con protecciones para el último ADMIN.
    PUT /api/users/{user_id} update_user Actualiza datos, rol o estado de un usuario con protecciones para el último ADMIN.
    POST /api/users/{user_id}/reset-password reset_password Restablece la contraseña de un usuario y revoca sus sesiones previas. Exclusivo para administradores.
