    app.services.audit_service¶

    Servicio de auditoría inmutable de Vigía. Registra eventos críticos del sistema en audit_log garantizando: 1. Ningún secreto ni credencial en details_json. 2. En logins fallidos jamás se guarda la contraseña o texto ingresado como tal. 3. Fallo silencioso con advertencia en log: un error al auditar jamás rompe la operación de negocio.

    Funciones

    • sanitize_audit_details(details: Optional[Dict[str, Any]]) -> Optional[str]: Sanitiza y serializa el diccionario de detalles a JSON. Elimina claves sensibles y enmascara texto.
    • record_audit_event(db: Session, action: str, entity: str, entity_id: Optional[Union[str, int]]=None, actor_user_id: Optional[int]=None, project_id: Optional[int]=None, details: Optional[Dict[str, Any]]=None) -> Optional[AuditLog]: Registra un evento en la tabla audit_log. Un fallo al auditar NO rompe la operación (emite advertencia en logs).

    app.services.ci_token_service¶

    Servicio de gestión de Tokens de CI por proyecto (Fase 4: CI/CD Tokens). Genera tokens criptográficos con prefijo 'vgi_', calcula hash SHA-256 para almacenamiento seguro y valida tokens en tiempo constante.

    Funciones

    • generate_project_ci_token(db: Session, project_id: int, name: str, user_id: Optional[int]=None) -> Tuple[ProjectApiToken, str]: Genera un token seguro formato 'vgi_' + 40 chars urlsafe. Guarda token_hash (SHA-256) y token_prefix (primeros 8 caracteres). Devuelve la entidad y el token en claro (solo visible en creación).
    • list_project_ci_tokens(db: Session, project_id: int) -> List[ProjectApiToken]: Lista todos los tokens creados para el proyecto ordenados por fecha descendente.
    • revoke_project_ci_token(db: Session, project_id: int, token_id: int) -> ProjectApiToken: Revoca un token del proyecto estableciendo revoked_at.
    • authenticate_ci_token(db: Session, raw_token: str) -> Optional[ProjectApiToken]: Valida un token con prefijo 'vgi_' mediante SHA-256 y comparación en tiempo constante. Si es válido y no está revocado, actualiza last_used_at y devuelve el objeto.

    app.services.email_service¶

    Servicio centralizado de envío de correos electrónicos y gestión de códigos de autenticación. Fase D - Verificación de correo, recuperación de contraseña y avisos transaccionales.

    Funciones

    • get_utc_now() -> datetime
    • hash_code(code: str) -> str: Calcula el hash SHA-256 en hexadecimal del código de 6 dígitos.
    • send_email(to: str, subject: str, text: str, html: str) -> bool: Envía un correo electrónico transaccional con versión HTML y texto plano mediante SMTP (STARTTLS). Timeout de 10 segundos. Nunca propaga excepciones al llamador: ante cualquier error registra en logs y devuelve False.
    • build_email_template(title: str, intro: str, code: Optional[str]=None, action_url: Optional[str]=None, action_text: Optional[str]=None, footer_note: Optional[str]=None) -> Tuple[str, str]: Construye la plantilla sobria HTML (sin dependencias ni imágenes externas) y la versión en texto plano correspondiente.
    • issue_email_code(db: Session, user: User, purpose: str) -> str: Genera un código numérico seguro de 6 dígitos con secrets, invalida cualquier código anterior del mismo propósito para este usuario, guarda su hash SHA-256 en la base de datos y retorna el código en claro para su despacho.
    • verify_email_code(db: Session, user: User, purpose: str, raw_code: str) -> Tuple[bool, str]: Valida el código de verificación o recuperación contra la base de datos. - Rechaza códigos expirados, ya utilizados o inexistentes. - 5 intentos fallidos invalidan definitivamente el código. - Si es válido, lo marca como utilizado y retorna (True, 'ok').
    • send_verification_email(user: User, code: str) -> bool: Envía el correo con el código de 6 dígitos para la verificación de cuenta.
    • send_password_reset_email(user: User, code: str) -> bool: Envía el correo con el código de 6 dígitos para recuperación de contraseña.
    • send_invitation_email(to_email: str, invited_by_name: str, project_name: str, role: str) -> bool: Envía el aviso por correo de una nueva invitación a un proyecto en Vigía.

    app.services.session_service¶

    Servicio de gestión de sesiones de usuario (RNF04). Controla: - Inactividad deslizante (SESSION_IDLE_MINUTES, default 30 min). - Tope absoluto de sesión de 24 horas. - Límite máximo de sesiones simultáneas por usuario (SESSION_MAX_PER_USER, default 5). - Hash SHA-256 de identificador de token (jti). - Resumen sanitizado de User-Agent (sin IP).

    Funciones

    • get_utc_now() -> datetime
    • get_session_idle_minutes() -> int: Retorna el tiempo de inactividad máximo permitido en minutos (default 30 min).
    • get_session_max_per_user() -> int: Retorna el número máximo de sesiones activas simultáneas por usuario (default 5).
    • hash_jti(jti: str) -> str: Genera el hash SHA-256 del jti para almacenamiento seguro.
    • summarize_user_agent(ua_raw: Optional[str]) -> str: Extrae un resumen estructurado y seguro del User-Agent: Navegador y Sistema Operativo. NUNCA incluye la cadena cruda completa ni direcciones IP.
    • create_user_session(db: Session, user_id: int, user_agent_raw: Optional[str]=None, jti: Optional[str]=None) -> Tuple[str, UserSession]: Crea una nueva sesión en user_sessions: 1. Genera un jti criptográfico único (o usa el provisto). 2. Aplica la política de máximo de sesiones (SESSION_MAX_PER_USER): si se supera, revoca la más antigua. 3. Fija expires_at con la inactividad inicial (tope absoluto 24 h). Retorna la tupla (jti_plano, objeto_UserSession).
    • validate_and_renew_session(db: Session, jti: str, user_id: int) -> Optional[UserSession]: Valida que la sesión exista, corresponda al usuario, no esté revocada y no haya expirado. Aplica renovación deslizante: actualiza last_seen_at como máximo una vez por minuto para no escribir en base de datos en cada petición, extendiendo expires_at respetando el máximo absoluto de 24 horas desde created_at. Retorna UserSession si es válida; None si es inválida/expirada/revocada.
    • is_session_valid(session: UserSession, now: Optional[datetime]=None) -> bool: Verifica si una sesión de usuario es válida (no revocada y no expirada).
    • revoke_session(db: Session, session_id: int, user_id: int) -> bool: Revoca una sesión específica perteneciente al usuario.
    • revoke_all_user_sessions(db: Session, user_id: int) -> int: Revoca todas las sesiones activas de un usuario (e.g. al cambiar la contraseña).
    • revoke_other_sessions(db: Session, user_id: int, current_jti: str) -> int: Revoca todas las sesiones activas del usuario EXCEPTO la actual.
    • get_user_sessions(db: Session, user_id: int, current_jti: Optional[str]=None) -> List[Dict[str, Any]]: Retorna la lista de sesiones activas del usuario, indicando cuál es la actual.
