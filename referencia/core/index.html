    app.core.cache¶

    Módulo de Caché HTTP y Caché en Memoria (RNF06). Proporciona: 1. Helpers para validación de ETag y generación de respuestas 304 Not Modified. 2. Caché en memoria con TTL configurable (METRICS_CACHE_SECONDS, default 60 s) para métricas de proyectos.

    Funciones

    • get_metrics_cache_ttl() -> int: Retorna el TTL en segundos para la caché de métricas (RNF06). Por defecto 60 s.
    • compute_etag(content: Any) -> str: Calcula un ETag fuerte basado en el hash SHA-256 del contenido serializado.
    • check_etag(request: Request, content: Any) -> Tuple[Optional[Response], str]: Comprueba si el encabezado If-None-Match de la solicitud coincide con el ETag del contenido. Retorna una tupla (response_304_or_None, etag_str). Si coincide, retorna (Response(status_code=304, headers={"ETag": etag}), etag). Si no coincide, retorna (None, etag).
    • apply_etag_to_response(response: Response, etag: str) -> Response: Agrega el encabezado ETag a la respuesta.
    • get_cached_project_metrics(project_id: int, ultimas: int) -> Optional[Any]: Obtiene las métricas de proyecto de la caché en memoria si no han expirado. Retorna None si no están en caché o si el TTL ha expirado.
    • set_cached_project_metrics(project_id: int, ultimas: int, data: Any) -> None: Guarda las métricas calculadas en la caché en memoria con la marca de tiempo actual.
    • invalidate_project_metrics_cache(project_id: Optional[int]=None) -> None: Invalida la caché de métricas. Si se especifica project_id, elimina solo las entradas de ese proyecto. Si project_id es None, vacía toda la caché de métricas.

    app.core.concurrency¶

    Módulo de control de concurrencia y resiliencia para ejecuciones SQL (Fase T3). Controla el número de ejecuciones concurrentes contra bases de datos objetivo a nivel global del proceso y por usuario o token de CI.

    ConcurrencyLimitExceeded (Exception)¶

    Excepción lanzada cuando se supera el límite global o por usuario de ejecuciones simultáneas.

    Métodos

    • __init__(self, message: str='El sistema está ocupado ejecutando otras pruebas. Intenta de nuevo en unos segundos.', retry_after: int=5)

    ExecutionConcurrencyLimiter¶

    Administrador thread-safe de cupos de ejecución de pruebas SQL. Aplica límites tanto globales (por proceso) como individuales (por usuario / token de CI).

    Propiedades

    • active_global: int

    Métodos

    • __init__(self)
    • get_max_global(self) -> int
    • get_max_per_user(self) -> int
    • active_for_key(self, key: str) -> int
    • acquire(self, client_key: str)

    Funciones

    • get_concurrency_client_key(req: Request, user=None) -> str: Obtiene la clave identificadora única del cliente para control de concurrencia.

    app.core.config¶

    Módulo Central de Configuración del Portal Integrador. Centraliza la obtención de variables de entorno y políticas por defecto fail-closed.

    Funciones

    • get_environment() -> str: Retorna el entorno de ejecución configurado en el sistema ('production', 'development', 'test', etc.). Por defecto asume 'production' (fail-closed por principios de seguridad).
    • get_trusted_proxy_count() -> int: Retorna la cantidad de proxies de confianza configurados para la extracción de IP real del cliente. Por defecto es 0 (ignora encabezados X-Forwarded-For y utiliza la IP directa del socket). En entornos tras reverse proxy de confianza (e.g. Azure App Service), debe configurarse en 1.
    • is_self_registration_allowed() -> bool: Determina si el autoregistro público de usuarios está habilitado. Por defecto es False (fail-closed).
    • is_google_auth_configured() -> bool: Determina si el inicio de sesión con Google está configurado. Requiere GOOGLE_CLIENT_ID y GOOGLE_CLIENT_SECRET.
    • get_google_config() -> dict: Retorna la configuración de Google OAuth si está configurada.
    • is_email_verification_required() -> bool: Determina si la verificación de correo electrónico es requerida para cuentas locales. Por defecto es True.
    • get_smtp_config() -> dict: Retorna la configuración del servicio SMTP.
    • get_public_config() -> dict: Retorna configuración pública no sensible para el frontend. NUNCA debe exponer secretos.

    app.core.html_versioning¶

    Módulo de inyección de versión en plantillas HTML y cabeceras de caché de estáticos. Reemplaza marcadores {{APP_VERSION}} y garantiza que todas las referencias a archivos .js y .css servidas lleven ?v=.

    Funciones

    • inject_version_into_html(html_text: str, app_version: Optional[str]=None) -> str: Inyecta la versión de la aplicación en el contenido HTML: 1. Reemplaza el marcador explícito {{APP_VERSION}}. 2. Asegura que cualquier referencia a scripts .js o estilos .css en src o href lleve el parámetro de versionado ?v=.

    app.core.logging_config¶

    Módulo de Logging Estructurado en JSON y Enmascaramiento de Secretos. Utiliza únicamente la librería estándar de Python (sin dependencias adicionales). Configurable mediante variables de entorno: - LOG_LEVEL: DEBUG, INFO, WARNING, ERROR, CRITICAL (default INFO) - LOG_FORMAT: json | texto (default json)

    JsonLogFormatter (logging.Formatter)¶

    Formateador de logs estructurados en JSON con la librería estándar. Campos: timestamp, nivel, logger, mensaje, request_id, user_id, ruta_plantilla, codigo, duracion_ms.

    Métodos

    • format(self, record: logging.LogRecord) -> str

    SecretMaskingFilter (logging.Filter)¶

    Filtro de logging que enmascara secretos y asocia variables de contexto.

    Métodos

    • filter(self, record: logging.LogRecord) -> bool

    Funciones

    • mask_secrets_in_text(text: str) -> str: Enmascara cualquier dato sensible en una cadena de texto.
    • setup_logging(): Configura el logging global según las variables de entorno LOG_LEVEL y LOG_FORMAT.

    app.core.validators¶

    Módulo de validadores de negocio para usuarios, correos y nombres. Fase D3 - Reglas de registro robustas y sanitización.

    Funciones

    • validate_username_rules(raw_username: str) -> str: Valida las reglas de nombre de usuario: - 3–30 caracteres. - Se normaliza a minúsculas. - Solo letras minúsculas, números, punto, guion y guion bajo. - Debe empezar con letra. - No puede ser solo números. - No puede terminar en punto. - Unicidad sin distinguir mayúsculas. - Lista de nombres reservados. Retorna el username normalizado. Lanza ValueError si no es válido.
    • validate_email_rules(raw_email: str) -> str: Valida las reglas de correo electrónico: - Normalización (trim + minúsculas). - Longitud máxima 150 caracteres. - Formato de correo electrónico válido. - Rechazo de dominios desechables/temporales con mensaje exacto: 'Usa un correo personal o institucional válido'. Retorna el email normalizado. Lanza ValueError si no es válido.
    • validate_full_name_rules(raw_name: str) -> str: Valida las reglas de nombre completo: - Trim de espacios. - 2–100 caracteres. - Sin etiquetas HTML ni URLs. - Al menos una letra. Retorna el nombre normalizado. Lanza ValueError si no es válido.

    app.core.version¶

    Funciones
