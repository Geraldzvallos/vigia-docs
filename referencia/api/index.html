    Referencia: app.api¶

    Detalle de cada clase con sus atributos, propiedades y métodos, generado desde el código y sus docstrings.

    app.api.admin_usage¶

    Endpoints de administración para telemetría y uso del producto Vigía. Permite consultar indicadores de actividad (DAU/WAU/MAU, adopción por módulo, tasas de error, distribuciones y latencias p50/p95). Acceso exclusivo para administradores globales (ADMIN).

    Funciones

    • get_usage_dashboard(desde: str=Query(..., description='Fecha inicial en formato YYYY-MM-DD'), hasta: str=Query(..., description='Fecha final en formato YYYY-MM-DD'), current_user: User=Depends(require_roles(UserRole.ADMIN.value)), db: Session=Depends(get_db)): Retorna el dashboard analítico de utilización de Vigía. Valida que el rango de consulta no sea posterior ni exceda los 180 días. Solo accesible para el rol ADMIN global.

    app.api.allowed_hosts¶

    Dominios permitidos para los casos API de un proyecto (RN18, anti-SSRF). Ver: cualquier miembro del proyecto. Agregar y quitar: OWNER (o ADMIN global).

    Funciones

    • list_allowed_hosts(project_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db))
    • add_allowed_host(project_id: int, payload: schemas.AllowedHostCreate, current_user: User=Depends(get_current_user), db: Session=Depends(get_db))
    • delete_allowed_host(project_id: int, host_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db))

    app.api.audit¶

    Endpoints de consulta de la bitácora inmutable de auditoría (Historial / Auditoría). Gobernanza RBAC: - ADMIN: acceso total a toda la bitácora del sistema y filtros globales. - OWNER: acceso restringido únicamente a los eventos de los proyectos donde es OWNER. - Demás roles (QA, DEV, DBA, USER): 403 Forbidden. - Anónimo: 401 Unauthorized. - Inmutabilidad estricta: Métodos PUT, PATCH y DELETE responden 405 Method Not Allowed.

    Funciones

    • list_audit_logs(start_date: Optional[datetime]=Query(None, description='Fecha de inicio (ISO-8601)'), end_date: Optional[datetime]=Query(None, description='Fecha de fin (ISO-8601)'), action: Optional[str]=Query(None, description='Filtrar por acción'), actor_user_id: Optional[int]=Query(None, description='Filtrar por ID del usuario actor'), user_id: Optional[int]=Query(None, description='Alias para actor_user_id'), project_id: Optional[int]=Query(None, description='Filtrar por proyecto'), page: int=Query(1, ge=1, description='Número de página'), page_size: int=Query(20, ge=1, le=100, description='Tamaño de página'), current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Consulta paginada con filtros de la bitácora de auditoría. ADMIN ve todo el sistema. OWNER ve únicamente eventos de proyectos donde es OWNER. Demás roles reciben 403 Forbidden.
    • audit_immutable_protection(request: Request)

    app.api.auth_google¶

    Endpoints de autenticación federada con Google OpenID Connect (Fase B). Provee /api/auth/google/login y /api/auth/google/callback.

    Funciones

    • google_login(request: Request): Inicia el flujo de autenticación OpenID Connect con Google. Genera state y nonce criptográficos, los almacena en una cookie firmada y redirige a la pantalla de consentimiento de Google.
    • google_callback(request: Request, state: Optional[str]=None, code: Optional[str]=None, error: Optional[str]=None, db: Session=Depends(get_db)): Procesa el callback de Google tras el consentimiento del usuario. Valida state y nonce, verifica el ID Token, autentica o registra al usuario y emite la sesión JWT correspondiente.

    app.api.auth_sessions¶

    Endpoints para la gestión de sesiones activas del usuario (RNF04). Permite listar sesiones (marcando la actual), revocar una sesión específica o revocar todas las demás. Los tokens de CI (vgi_) NO se ven afectados por este módulo.

    Funciones

    • list_my_sessions(request: Request, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)) -> List[Dict[str, Any]]: Retorna la lista de sesiones activas del usuario actual, marcando cuál es la actual.
    • revoke_my_session(session_id: int, request: Request, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Revoca una sesión específica del usuario. Si no existe o no le pertenece, responde 404.
    • revoke_other_sessions_endpoint(request: Request, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Cierra todas las demás sesiones activas del usuario, conservando únicamente la actual.

    app.api.ci¶

    Endpoints de Integración CI/CD (Fase 4). Permite disparar ejecuciones de suites de prueba mediante tokens de CI por proyecto y consultar el historial de ejecuciones de pipelines (CiRun).

    Funciones

    • trigger_ci_run(payload: schemas.CiTriggerRequest, req: Request, db: Session=Depends(get_db)): Dispara la ejecución automatizada de una Suite mediante Token de CI por proyecto. Solo accesible mediante autenticación de token de proyecto (vgi_...). Verifica que la suite y el perfil pertenezcan estrictamente al proyecto del token.
    • list_ci_runs(req: Request, project_id: Optional[int]=Query(None), branch: Optional[str]=Query(None), status_filter: Optional[str]=Query(None, alias='status'), skip: int=Query(0, ge=0), limit: int=Query(50, ge=1, le=100), auth_user=Depends(get_current_user_or_ci), db: Session=Depends(get_db)): Lista las ejecuciones de pipelines (CiRun) paginadas y filtrables. Accesible para miembros con sesión del proyecto y para tokens de CI del proyecto.
    • get_ci_run_detail(run_id: int, req: Request, auth_user=Depends(get_current_user_or_ci), db: Session=Depends(get_db)): Obtiene el detalle de un CiRun junto a sus ejecuciones históricas asociadas. Accesible para miembros del proyecto o para el token de CI del proyecto.

    app.api.connections¶

    Endpoints REST para la gestión de Perfiles de Conexión Oracle (sin persistencia de contraseñas). Fase A - Aislamiento por proyecto, roles (DBA, OWNER, ADMIN), protección SSRF y perfiles demo.

    Funciones

    • create_connection_profile(profile: schemas.ConnectionProfileCreate, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Crea un nuevo perfil de conexión Oracle para un proyecto. Permitido únicamente a DBA u OWNER del proyecto, o ADMIN global. Valida contra destinos de red privada o restringidos (SSRF).
    • get_connection_profiles(project_id: Optional[int]=Query(None), skip: int=Query(0, ge=0), limit: int=Query(100, ge=1, le=100), auth_user: Optional[User]=Depends(get_current_user_or_ci), db: Session=Depends(get_db)): Obtiene la lista de perfiles de conexión filtrados opcionalmente por proyecto. Si el usuario no es miembro del proyecto especificado, responde 404 (aislamiento).
    • get_connection_profile(connection_id: int, auth_user: Optional[User]=Depends(get_current_user_or_ci), db: Session=Depends(get_db)): Obtiene un perfil de conexión por su ID. Si el usuario no es miembro del proyecto al que pertenece la conexión, responde 404.
    • update_connection_profile(connection_id: int, profile_data: schemas.ConnectionProfileUpdate, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Actualiza la información de un perfil de conexión. Permitido a DBA u OWNER del proyecto, o ADMIN global. Los perfiles is_demo no pueden modificarse.
    • delete_connection_profile(connection_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Elimina un perfil de conexión. Permitido a DBA u OWNER del proyecto, o ADMIN global.
    • test_connection_profile(connection_id: int, request: schemas.TestConnectionRequest, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Prueba la conectividad de un perfil Oracle. Permitido a DBA u OWNER del proyecto, o ADMIN global. Si el perfil es de demostración (is_demo=True), inyecta automáticamente DEMO_ORACLE_PASSWORD.

    app.api.executions¶

    Router de Ejecución de Pruebas (SQL y API) desacoplado utilizando el Servicio Centralizado de Ejecución. Fase A - Aislamiento por proyecto, roles (QA, OWNER, ADMIN o CI), rate limiting y perfiles demo.

    Funciones

    • apply_execution_rate_limit(req: Request, user=None): Aplica rate limiting sobre endpoints de ejecución por usuario o por IP.
    • execute_target_sql(request: schemas.ExecutionRequest, req: Request, auth_user=Depends(get_current_user_or_ci), db: Session=Depends(get_db)): Ejecuta una sentencia SQL aislada aplicando las políticas de seguridad del ambiente.
    • run_test_case(test_case_id: int, db_credentials: schemas.TestCaseExecutionRequest, req: Request, current_user=Depends(get_current_user_or_ci), db: Session=Depends(get_db)): Orquestador Principal: Recupera un caso de prueba guardado y lo ejecuta utilizando el servicio centralizado de ejecución. Regla: Solo se ejecutan casos en estado 'APROBADO'. Permitido a QA, OWNER en el proyecto, ADMIN global o CI API Key.
    • run_test_suite(suite_id: int, db_credentials: schemas.SuiteExecutionRequest, req: Request, current_user=Depends(get_current_user_or_ci), db: Session=Depends(get_db)): Ejecuta en ráfaga todos los casos de prueba de una Suite utilizando una conexión única. Regla: Solo los casos APROBADO se ejecutan en suites y en CI; los demás se reportan como omitidos en el resumen. Permitido a QA, OWNER en el proyecto, ADMIN global o CI API Key.

    app.api.invitations¶

    Endpoints para la gestión de Invitaciones a proyectos. Fase C - Flujo de invitación con consentimiento y aceptación.

    Funciones

    • get_my_pending_invitations(current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Retorna la lista de invitaciones pendientes para el usuario en sesión. Incluye nombre del proyecto, rol y quién invitó.
    • accept_invitation(invitation_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Acepta una invitación pendiente y crea la membresía correspondiente. Solo el invitado puede aceptar (cualquier otro recibe 404). Si ya no está pendiente, responde 409.
    • decline_invitation(invitation_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Rechaza una invitación pendiente. Solo el invitado puede rechazar (cualquier otro recibe 404). Si ya no está pendiente, responde 409.

    app.api.projects¶

    Endpoints REST para la gestión de Proyectos y Membresías (Fase A).

    Funciones

    • create_project(project: schemas.ProjectCreate, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Crea un nuevo proyecto en el espacio de trabajo. Cualquier usuario autenticado puede crear proyectos y queda asignado como OWNER. Límite configurable por MAX_PROJECTS_PER_USER (por defecto 5; ADMIN sin límite).
    • get_projects(req: Request, skip: int=Query(0, ge=0), limit: int=Query(100, ge=1, le=100), auth_user: Optional[User]=Depends(get_current_user_or_ci), db: Session=Depends(get_db)): Obtiene la lista de proyectos con paginación estricta. Filtra únicamente los proyectos donde el usuario es miembro activo (ADMIN ve todo; CI ve todo). Soporta validación de caché ETag y respuesta 304 Not Modified.
    • get_project(project_id: int, auth_user: Optional[User]=Depends(get_current_user_or_ci), db: Session=Depends(get_db)): Obtiene los detalles de un proyecto por su ID. Si el usuario no es miembro, responde 404 para aislar la existencia del recurso.
    • update_project(project_id: int, project_data: schemas.ProjectUpdate, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Actualiza la información de un proyecto existente. Permitido únicamente a usuarios con rol OWNER en el proyecto o ADMIN global.
    • delete_project(project_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Elimina un proyecto si el usuario es OWNER o ADMIN y no tiene dependencias activas.
    • get_project_members(project_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Lista todos los miembros del proyecto. Requiere ser miembro del proyecto o ADMIN global. Privacidad: el correo de los miembros solo debe verlo el OWNER del proyecto o un ADMIN; para el resto, la API debe devolver email = null.
    • add_project_member(project_id: int, payload: schemas.ProjectMemberCreate, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Invita a un usuario al proyecto por username o email. En Fase C, crea una invitación pendiente en vez de la membresía directa. Solo permitido a usuarios con rol OWNER en el proyecto o ADMIN global.
    • get_project_invitations(project_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Lista las invitaciones pendientes del proyecto. Solo permitido para el OWNER del proyecto o ADMIN global.
    • cancel_project_invitation(project_id: int, invitation_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Cancela una invitación pendiente del proyecto. Solo permitido para el OWNER del proyecto o ADMIN global.
    • update_project_member(project_id: int, user_id: int, payload: schemas.ProjectMemberUpdate, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Cambia el rol de un miembro del proyecto. Solo permitido a usuarios con rol OWNER en el proyecto o ADMIN global. Protección: No se puede degradar al último OWNER.
    • remove_project_member(project_id: int, user_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Quita un miembro del proyecto. Permitido a OWNER o ADMIN global, o al propio usuario si desea abandonar el proyecto. Protección: No se puede quitar ni salir siendo el último OWNER.
    • create_project_ci_token(project_id: int, payload: schemas.ProjectCiTokenCreateRequest, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Crea un nuevo token de CI para el proyecto. Solo permitido para el OWNER del proyecto o ADMIN global. Devuelve el token en texto plano UNA ÚNICA VEZ.
    • get_project_ci_tokens(project_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Lista todos los tokens de CI del proyecto (sin exponer el secreto en claro). Solo permitido para el OWNER del proyecto o ADMIN global.
    • revoke_ci_token(project_id: int, token_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Revoca un token de CI del proyecto. Solo permitido para el OWNER del proyecto o ADMIN global.

    app.api.runs¶

    Corridas de prueba (test runs). - Iniciar, ejecutar automáticos y finalizar: OWNER o QA (igual que ejecutar suites). - Registrar resultados manuales: OWNER, QA o DEV. - Ver: cualquier miembro del proyecto.

    Funciones

    • start_run(suite_id: int, payload: schemas.TestRunCreate, req: Request, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Crea la corrida con un resultado por caso y ejecuta los casos API (y SQL si llegan credenciales).
    • execute_pending(run_id: int, payload: schemas.TestRunCreate, req: Request, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Ejecuta los casos automáticos que quedaron pendientes (por ejemplo, SQL sin conexión al iniciar).
    • list_runs(project_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db))
    • get_run(run_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db))
    • record_manual_result(run_id: int, result_id: int, payload: schemas.ManualResultUpdate, current_user: User=Depends(get_current_user), db: Session=Depends(get_db))
    • finish_run(run_id: int, current_user: User=Depends(get_current_user), db: Session=Depends(get_db)): Cierra la corrida, recalcula los totales, crea los tickets de los manuales fallidos y avisa por webhook.

    Funciones
