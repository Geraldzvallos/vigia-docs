    app.security.auth¶

    Módulo de Seguridad, Autenticación y Autorización basada en Roles (RBAC). Gestiona el hash de contraseñas con bcrypt, tokens firmados de sesión JWT y dependencias de FastAPI para validar roles y usuarios.

    Funciones

    • hash_password(plain_password: str) -> str: Genera un hash seguro para la contraseña utilizando bcrypt.
    • verify_password(plain_password: str, hashed_password: str) -> bool: Verifica si la contraseña en texto plano coincide con el hash bcrypt.
    • validate_password_strength(password: str, username: str='', email: str='') -> Optional[str]: Valida la fortaleza de la contraseña según la política de seguridad del portal: - Mínimo 10 caracteres. - No puede consistir únicamente en números. - Debe ser diferente del nombre de usuario. - Debe ser diferente del correo electrónico. Retorna None si es válida; un mensaje explicativo si no cumple la política.
    • get_session_secret() -> Optional[str]: Obtiene el secreto criptográfico para firma de tokens. Si APP_ACCESS_ENABLED es true y no está configurado o tiene menos de 32 caracteres, devuelve None: no hay secreto por defecto (obliga a devolver 503).
    • create_session_token(user_id: int, username: str='', role: str='USER', token_version: int=1, expires_in_seconds: int=86400, jti: Optional[str]=None, db: Optional[Session]=None, user_agent_raw: Optional[str]=None) -> str: Crea un token JWT firmado con user_id, role, token_version, jti y expiración (exp). Si no se proporciona un jti, genera uno criptográfico y lo registra en user_sessions si es posible.
    • verify_session_token(token: str) -> Optional[dict]: Decodifica y verifica la firma y la fecha de expiración del token. Retorna el payload si es válido; si expiró, fue alterado o es inválido, retorna None.
    • get_token_from_request(request: Request) -> Optional[str]: Extrae el token de la cookie 'session_token' o del encabezado 'Authorization: Bearer '.
    • get_current_user(request: Request, db: Session=Depends(get_db)) -> User: Dependencia FastAPI que obtiene y valida el usuario actual a partir del token firmado. Lanza 401 si no está autenticado, si el token expiró/es inválido, si el usuario está inactivo o si token_version no coincide con el registro en la base de datos (sesión revocada).
    • require_roles(*roles: str) -> Callable: Fábrica de dependencias que exige que el usuario autenticado posea al menos uno de los roles globales indicados. Lanza 403 Forbidden si el rol no está permitido.
    • require_user_or_ci(*roles: str) -> Callable: Dependencia para endpoints accesibles tanto por corredores CI/CD (API Key o Token de CI) como por usuarios interactivos con roles específicos.
    • get_current_user_or_ci(request: Request, db: Session=Depends(get_db)) -> Optional[User]: Dependencia de lectura compartida: retorna None si es API Key de CI o Token de CI, o User si es usuario interactivo.

    app.security.google_auth¶

    Módulo de integración con Google OpenID Connect (Fase B). Maneja la generación de state/nonce en cookies firmadas, URLs de autorización, intercambio de códigos por tokens y verificación de ID Tokens.

    Funciones

    • get_oauth_serializer() -> URLSafeTimedSerializer
    • generate_state_and_nonce() -> Tuple[str, str]: Genera valores criptográficos aleatorios para state y nonce.
    • create_oauth_cookie_value(state: str, nonce: str) -> str: Firma el state y nonce en un string seguro para almacenar en cookie HttpOnly.
    • verify_oauth_cookie_value(cookie_val: Optional[str], state_from_query: str) -> Optional[Dict[str, Any]]: Verifica que la cookie exista, esté firmada, no haya expirado (10 min) y que el state coincida con el provisto en el query param del callback.
    • build_authorization_url(state: str, nonce: str) -> str: Construye la URL de redirección hacia Google OAuth 2.0.
    • exchange_code_for_tokens(code: str) -> Dict[str, Any]: Intercambia el authorization code por tokens en el endpoint de Google. En pruebas automatizadas esta función puede ser reemplazada con un mock.
    • verify_google_id_token(id_token: str, expected_nonce: Optional[str]=None) -> Dict[str, Any]: Decodifica y valida las aserciones del ID Token de Google: - Issuer: https://accounts.google.com o accounts.google.com - Audience: GOOGLE_CLIENT_ID - Nonce: debe coincidir con el generado en la sesión - Expiración: debe ser futuro - email_verified: debe ser True

    app.security.host_validator¶

    Módulo de Validación de Destinos de Conexión (Protección Anti-SSRF / Escaneo de Red). Previene que el portal sea utilizado para escanear redes privadas, interfaces loopback, redes link-local o endpoints de metadatos de proveedores de nube (AWS, GCP, Azure 169.254.169.254).

    Funciones

    • is_private_or_restricted_ip(ip_str: str) -> bool: Evalúa si una dirección IP pertenece a rangos privados, loopback, link-local o metadatos.
    • validate_db_host(host: str, is_demo: bool=False) -> None: Valida el host de conexión contra la política de restricción de red. Exenta automáticamente los perfiles de demostración (is_demo=True). Lanza HTTPException 400 si la dirección está restringida.

    app.security.permissions¶

    Módulo Reutilizable de Autorización y Permisos por Proyecto (Fase A). Implementa el modelo de membresía y roles por proyecto (OWNER, QA, DEV, DBA).

    ProjectPermissionRole (str, enum.Enum)¶

    Valores: OWNER, QA, DEV, DBA

    Funciones

    • get_project_membership(db: Session, project_id: int, user_id: int) -> Optional[ProjectMember]: Obtiene el registro de membresía de un usuario en un proyecto.
    • get_user_role_in_project(db: Session, project_id: int, user: Optional[User]) -> Optional[str]: Retorna el rol efectivo del usuario en el proyecto. Si el usuario es administrador global de la plataforma (ADMIN), se considera OWNER en todos los proyectos. El acceso a un proyecto se decide SOLO por project_members, salvo ADMIN global.
    • get_user_accessible_project_ids(db: Session, user: Optional[User]) -> Optional[List[int]]: Retorna la lista de IDs de proyectos a los que el usuario tiene acceso. Si es administrador global (ADMIN), retorna None (lo que significa acceso irrestricto a todos). Para cualquier otro usuario, se decide SOLO por las membresías en project_members.
    • verify_project_access(project_id: Optional[int], user: Optional[User], db: Session, required_roles: Optional[List[str]]=None) -> str: Verifica que el proyecto exista y que el usuario sea miembro con rol suficiente. Regla crítica de aislamiento de seguridad: - Si el usuario no es miembro (y no es ADMIN global), responde 404 (no 403) para no revelar la existencia del proyecto a terceros no autorizados. - Si es miembro pero no tiene el rol necesario dentro del proyecto, responde 403.
    • check_ticket_assignable_member(db: Session, project_id: int, target_user_id: int) -> User: Valida que el usuario asignado a un ticket de defecto sea un miembro activo del proyecto con rol DEV u OWNER. Lanza HTTPException 400 si no cumple con las condiciones.

    app.security.rate_limiter¶

    Módulo de Limitación de Tasa (Rate Limiting) en Memoria con Ventana Deslizante.

    Funciones

    • get_client_ip(request: Request) -> str: Obtiene la dirección IP real del cliente considerando la cantidad de proxies de confianza. - Si TRUSTED_PROXY_COUNT == 0 (por defecto): ignora X-Forwarded-For y usa la IP directa de la conexión. - Si TRUSTED_PROXY_COUNT = N > 0: toma la IP en la posición N contando desde la derecha de X-Forwarded-For (la que agregó el proxy de confianza más externo). NOTA: En entornos con reverse proxy como Azure App Service, se debe configurar TRUSTED_PROXY_COUNT=1.
    • check_rate_limit(key: str, max_requests: int, window_seconds: int=60) -> Tuple[bool, int]: Verifica si una clave ha superado el número de solicitudes en la ventana deslizante. Retorna (is_allowed, retry_after_seconds).
    • enforce_rate_limit(key: str, max_requests: int, window_seconds: int=60): Lanza HTTPException 429 si se excede la tasa de peticiones.
    • reset_rate_limiter(): Limpia todos los contadores de rate limiting (utilizado principalmente para tests).

    app.security.sql_policy¶

    Módulo de políticas SQL para el Framework de Pruebas. Aplica bloqueos DML en Producción y reglas estrictas en todos los ambientes.

    Funciones

    • validate_sql_statement(query: str, environment_type: str='TEST', confirm_staging_dml: bool=False) -> Tuple[bool, str, str]: Valida la sentencia SQL utilizando sqlparse para distinguir código SQL de literales de texto y comentarios. Aplica reglas específicas según el environment_type.
